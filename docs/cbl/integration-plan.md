# Donor integration plan for the RTX 5080

Start only after the owner authorizes the integration. This plan was prepared against `integrate-fxceless-pr81` at `1bc0760`, with fxceless parent `c96b4f2`. Preserve this known build, the two save snapshots, and the current research edits. The first acceptance target is opaque room geometry in the prison. The hallway, exterior and cashier are progressively broader checks. See [rendering evidence and checkpoints](next-renderer-work.md).

## Execution order after approval

1. **Pin and compare.** Fetch the three donor heads into explicit refs, recording full SHAs and parentage. Resolve the AnyXboxX gitlink and compare its actual code repo against the base listed in the manifest. Verify ancestry and equivalent diffs with `merge-base`, `log --left-right --cherry-pick`, and targeted source diffs. For patches copied into larger commits, inspect the affected implementation and tests. Scope each patch by dependency, existing equivalent, expected result, and author before applying it.
2. **Prepare an isolated worktree and baseline.** Branch from `1bc0760`. Keep the current branch, executable and uncommitted research available. Give the candidate its own build output and use copies of the prison checkpoint in runtime data roots accepted by VIctory. Record build, effective relay setting, display settings, driver, and cache state. The prison and later exterior snapshots are archived independently.
3. **Land the coherent fxceless memory set.** Prefer merging a pinned fxceless descendant if its intervening changes fit the comparison and its defaults can be matched. If the intervening range mixes unrelated changes or defaults, bring over the smallest dependency-complete memory set in reviewable commits. Preserve local descriptor-only handling from PR #81 when resolving translator overlap. Keep the aliased-page guard and buffered reads together, review DirectStorage write notification and retry behavior, and keep optional residency and accounting switches at their documented defaults. Run a Windows diagnostic build, relevant donor checks and the prison A/B before adding another donor.
4. **Select remaining AnyXboxX fixes.** PRs #81, #82 and #11 already have equivalents. Compare #63 with the existing texture rechecks, #71 with relay and copy-back code, #32 with render target format handling, and #77 and #83 with current shader lowering. Compare Yorivel's DirectStorage notification commits `e49864a` and `bf870de` against the selected fxceless memory path so a single write is handled coherently. Review #358 alongside the same page lifetime code. Keep #374 for the BC7 decoder, #349 for shader division edge cases, #353 for image sampling, #355 for wave and f16 operations, and #386 and #396 for sampler and rectangle handling. Port missing fixes in small groups with distinct validation. A verified format or shader correction can stand on its own even if the current screenshot has several causes. Evaluate the XG layout correction against a matching layout sample if texture corruption remains.
5. **Retest renderer correctness before performance.** Compare the prison ceiling and hallway at entry, 30 seconds and 90 seconds, then after a small turn. Repeat at least once because the gap varies between launches. Record visible coverage, device loss, DirectStorage errors, frame time and descriptor or pipeline diagnostics. A ceiling that appears only after waiting is partial progress. Use the later save to check the exterior independently and replay to the cashier only after the short comparisons. If a gap remains, use `VICTORY_WALLS_TRACE` when available or the planned one-frame depth and operation capture. Do not promote a batch whose geometry or reload behavior regresses.
6. **Queue separate experiments.** Evaluate NVIDIA wave32 translation for confirmed refused PSOs, #187 or other relay changes for measured throughput after geometry is stable, and #156 for static shadows with the dynamic BVH builder off. Compare the local warmup trial `590125d`, fxceless warmup and AnyXboxX's #282 port before selecting one cache implementation. Intro pacing remains deferred unless it affects the rendering investigation.
7. **Record credits and prepare review.** Preserve source authors and co-author trailers for direct ports, `-x` provenance for cherry-picks and source URLs plus donor SHAs for adaptations. Update the [patch provenance ledger](patch-provenance.md) with local SHAs, acceptance evidence and omitted or superseded patches. Keep the candidate branch reviewable before promotion to main.
